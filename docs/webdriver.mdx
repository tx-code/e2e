`@e2e-dev/webdriver` implements the public engine contract using Selenium.
This package is available in this fork's workspace and has not been published
to npm. Build `e2e` and the engine before consuming them through workspace or
file dependencies. `e2e init` does not scaffold this engine yet.

## Own a session per attempt

The session factory runs in the worker for every attempt, repeats included.
It receives the target's declared app, environment, and abort signal. Return
a driver and a cleanup callback that releases only resources you created.
An attached application keeps its existing document. Navigation is opt-in.

```ts
import type { E2EConfig } from 'e2e';
import { webdriver } from '@e2e-dev/webdriver';
import { Builder } from 'selenium-webdriver';

export default {
  targets: [{
    app: { url: 'http://127.0.0.1:3000' },
    engine: webdriver({
      navigation: true,
      async createSession() {
        const driver = await new Builder().forBrowser('MicrosoftEdge').build();
        return { driver, close: () => driver.quit() };
      },
    }),
  }],
  workers: 1,
} satisfies E2EConfig;
```

For an embedded document, let the factory create or attach the driver, and
leave `navigation` off. Select the intended window in the factory before
returning it. The engine never selects a different document on its own.

## Drive the flow through e2e

```ts
import { test } from '@e2e-dev/webdriver';
import { expect } from 'e2e';

test('fills the form', async ({ app, screen }) => {
  await app.open('/');
  await screen.getByLabel('Display name').fill('Sample');
  await screen.getByRole('button', 'Apply').tap();
  await expect(screen.getByRole('status', 'Result')).toContainText('Sample');
});
```

Use `webdriver.locator(cssOrXPath)` for attributes that have no semantic
query. `webdriver.evaluate` is for trusted test reads; use locator actions
to keep input dispatch and its outcome in the e2e trace.

<CodeGroup>
```bash npm
npx e2e run tests/form.e2e.ts --repeat-each 3 --reporter list,junit,markdown
```
```bash pnpm
pnpm exec e2e run tests/form.e2e.ts --repeat-each 3 --reporter list,junit,markdown
```
```bash bun
bunx e2e run tests/form.e2e.ts --repeat-each 3 --reporter list,junit,markdown
```
</CodeGroup>

The runner owns assertions, retries, action recording, and reports. Add a
model to use `agent.act`, then verify the goal with a locator assertion so
the replay cache can save its actions. A stable replay needs no model call;
changed controls can hand execution back to the model. See [Caching](/cache).

## Measurements and limits

### Native Windows file dialogs

The optional `@e2e-dev/webdriver/windows` entry adds native window tools.
The factory captures the process it owns with `captureWindowsProcess(pid)`;
`windowsDialogTools({ owner, files, saveFiles })` returns tools for the agent's `tools`
configuration. `owner` returns that identity while the attempt is active,
and `files` maps aliases to trusted local paths. Optional `saveFiles` maps
destination aliases to new file paths, or callbacks returning a fresh
path for the current attempt.

`native_windows` reads owned windows and dialogs. `choose_native_file`
selects a configured alias in an open file picker. `save_native_file`
submits a configured Save As destination and refuses existing paths.
`registered_files` reads file existence and byte sizes, not contents.
`cancel_native_dialog`
closes an owned dialog. Every operation checks the process creation time
and window ownership. No file contents, edit values, or screenshots are
returned by these tools.

For file selection and saving, `windowId` is optional. When omitted, the
helper selects exactly one enabled, visible dialog of the requested kind
within the owned process. Zero matches or multiple matches refuse the
operation before typing or clicking. The agent can then inspect
`native_windows` and supply an explicit id. Cancellation always requires an
explicit id. Automatic selection does not retry or enable cache replay.

The implementation uses Windows PowerShell and Windows messages, alongside
the DOM WebDriver transport. Standard Open dialogs with English, Chinese,
German, French or Portuguese Open and Save buttons are supported; other native
dialog types cannot select files. File selection, saving and cancellation are
mutating project tools and are not zero-call cache replays. Use a separate
preparation step, then verify DOM goals with locator assertions.

### Local screenshot evidence

With a trusted `screenshot` provider configured, call
`await app.screenshot('before-edit')` before a flow and
`await app.screenshot('after-verification')` after its assertions. The runner
attaches these files to the attempt's local report and trace. It also requests
a failure screenshot when a test fails. A refused or unavailable screenshot
must not be mistaken for evidence of success.

The neutral WebDriver testbed demonstrates these checkpoints in its native
Open/Save flow and in `tests/screenshots.e2e.ts`; `tests/failure.e2e.ts`
demonstrates automatic failure capture. Its provider only accepts the owned
testbed page without password inputs or frames. This fixture-specific guard
is not a general masking solution for other applications.

WebDriver screenshots cover the page viewport, not Windows file dialogs or
the desktop. These report artifacts do not enable model vision and are not
uploaded by the testbed. Keep screenshot directories out of source control.

### Annotating local screenshots

The `@e2e-dev/webdriver/annotations` entry exports
`screenshotAnnotationTools({ session, screenshot })`. `session` returns the
current owned `WebDriverSession`; `screenshot(session, signal)` returns a
trusted source-masked viewport PNG. Spread the returned tools into the
agent's `tools` configuration.

Ask the agent to record an annotated screenshot and name the controls and
captions. Its `annotate_screenshot` tool accepts up to eight exact
`{ role, name, text }` targets, draws numbered red boxes, and adds captions
below the image. Both the unchanged original and the annotated copy are
attached to that report step. No page edits or model image uploads occur.
The default artifact store keeps files local; a custom uploading store
changes that behavior.

Targets must be unique, stable, uncovered and fully within the main-document
viewport. The tool refuses unsuitable targets or image dimensions. It does
not locate canvas objects, native dialogs or frame contents. Chinese captions
require an installed CJK font. Captions are literal text, not proof of success
or a secret-redaction mechanism. Keep assertions and source masking in place.

Read-only tools are not replay actions. For fresh evidence on every run,
use a separate evidence goal with caching disabled. See the neutral
testbed's `tests/annotations.e2e.ts` and `e2e.native.config.ts` for a working
natural-language example.

### Timing and unsupported operations

Enable `metrics: true` to record observation, locator, and reference-resolution
times through the local app-log channel. No document content is included in
those measurements. Read model usage and cache outcomes separately from
the e2e report; `agent.act` time includes model and input-dispatch latency.

The initial verification target is Edge on Windows. Native main-document
DOM queries and common input actions are implemented. Frames, shadow roots,
Grid deployments, focused-field keyboard tools, coordinates, videos, and
saved sessions have not been implemented or verified. Unsupported actions
are not advertised to the agent.

Screenshots require a host-provided `screenshot(session, context)` callback
returning source-masked PNG bytes. When the host cannot prove masking, omit
the callback; the engine then declares no screenshot capability. It does
not expose unmasked model pixels.
